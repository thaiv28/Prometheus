# Prometheus research reproduction

No production source modifications or merge are part of this work. Main revision: `ac5745ca1982d7347d7caee2f98f70f7f1832c53`; draft research source: `dd84749b364d4580b41e7236ca98188f6a6d6596`.

The archive includes scored forecasts, machine-readable results, derived analysis features, protocols, sources/hashes, and research scripts. It excludes the 833 MB raw CSV corpus and rebuilt SQLite DB. All output is retrospective research, not deployable coefficients.

Place this `experiments` directory next to a fresh `prometheus-audit` clone at the pinned revision. Use `uv sync --frozen` in that clone, and add `pyarrow` to its environment without changing tracked dependency files. The downloader uses `requests` (install separately if absent); the pinned Prometheus Python version is 3.12+.

1. Run `experiments/acquire_mirror.py`; verify SHA256 against `mirror-manifest.json`. Mirror availability is not guaranteed. Official OE downloads hit quota during this run; do not silently substitute refreshed files.
2. Run `experiments/build_research_db.py` once against an absent research DB. It refuses to overwrite an existing DB. A scratch-local DB failed integrity during the first attempt; a fresh DB in `/tmp`, exposed only through the ignored DB-file symlink, rebuilt and passed `quick_check`.
3. Run `prepare.py`, then `verify_baseline.py`. Preparation uses the unmodified production Form/Elo functions; data cutoff is May 22, 2026, not October production coverage.
4. The patch Parquet source is `https://huggingface.co/datasets/HakimT/lol-champion-ranked-stats/resolve/main/data/train-00000-of-00001.parquet`. Preserve the included bytes/hash. Both win rate and pick rate equal to zero are treated as missing placeholders. The file lacks sample counts and verifiable collection timestamps.
5. Run `features.py`, then copy `features-clean.parquet` to `features-final.parquet`. This code computes pre-draft exposure from last-observed rosters and each player's last 40 professional champion appearances. Current picks only enter explicitly post-draft columns.
6. Run `evaluate.py`, `evaluate.py --chronological`, `dynamic.py`, `lineups.py`, and `bridges.py` from the research environment. Single BLAS/OMP thread was used. Static models tune only on 2022-23 and freeze through 2024+; online state updates wait until the next UTC day.
7. Fetch `scripts/research/draft_score.py` from the pinned draft revision into `draft_score_pr78.py` beside this directory. Run `draft_comparison.py` and `draft_comparison.py --chronological`, then `conditional_patch.py`. Draft features use strictly earlier OE timestamps, unlike the prior-day primary models; they require current picks. The draft helper's own main routine is not invoked, and no report in the clone is written.
8. `supplement.py` adds tournament/event cluster intervals and the directly matched market comparison. The released market archive source/hash is recorded in the report. No market blend is fit on those test outcomes.

Read `PROTOCOL.md` and the report before interpreting the numbers. `invalid-zero-placeholder-runs/` contains superseded scores using malformed source records; they are a data-quality diagnostic, not valid forecast evidence. The first dynamic run wrote forecasts/results successfully but failed serializing NumPy integer keys in an ancillary observation-fit file; the source has the serialization fix. Neither issue changes production code.

Nominal bootstrap intervals are conditional on fitted models and do not include all training or model-selection uncertainty. Multiple candidate families were inspected; no production threshold is declared passed from this study alone.

For the exploratory coverage-gated routing, run `availability_followup.py` after `supplement.py`. That routing was evaluated after inspecting subgroup results and is explicitly not untouched validation. Candidate forecast columns are meaningful for the final 2024+ evaluation only; outside that period many saved columns retain the production baseline as placeholders. Dev-selection utilities are in the results JSON and can be regenerated by the scripts. `analysis-features.parquet` contains the metadata and feature columns needed for the static comparisons; copy it to `features-final.parquet` for that review without rebuilding raw data. Full dynamic/history reruns require rebuilding the raw-data pipeline.
